# eid_der

Constrained DER reading for X.509 `TBSCertificate`s: every value a circuit takes from a certificate is read here, bound to the bytes that encode it.

## API

- **`read(der, offset, limit) -> Header`** returns `tag`, `header_len` and `len`.
  - Supported lengths: short form, `0x81 L` (L ≥ 0x80) and `0x82 L L` (first byte ≠ 0). Non-minimal and longer forms are rejected.
  - Asserts the element ends within `limit ≤ N`.
- **`expect(der, offset, limit, tag)`** is `read` plus a tag check.
- **`read_serial`** reads a positive INTEGER of 1–21 bytes (a 21st byte only as a leading `0x00`) and returns it right-aligned in 20 bytes.
- **`read_time`** reads UTCTime `YYMMDDHHMMSSZ` (years 50–99 → 19xx, 00–49 → 20xx, RFC 5280) or GeneralizedTime `YYYYMMDDHHMMSSZ` as unix seconds. It rejects non-digits, fractions and offsets, out-of-range fields, and years before 1970.
- **`parse_tbs(tbs)`** walks `SEQUENCE { [0] version, serialNumber, signature, issuer, validity, subject, subjectPublicKeyInfo, … }`. It returns `len` (from the outer header), `serial`, `not_before`, `not_after` and the `subjectPublicKeyInfo` offset. `validity` must contain exactly two times.
- **`assert_zero_padded(buf, len)`** asserts that bytes past `len` are zero, so a bucket buffer has one representation.

## Review notes

- **Cost of witness offsets.** Offsets are witness-dependent, so every read is a dynamic array access (a ROM/RAM lookup in the backend). Cost grows with the number of reads, not with the buffer size.
- **Day ranges aren't checked per month.** `days_from_civil` doesn't reject 31 February; such a certificate would parse to a nearby date. The certificate is signed, so this only matters if an issuer signs an invalid date.

## Tests

`src/vectors.nr` is generated by `eid-vectors der`. For 33 real certificates, `parse_tbs` must return exactly the length, serial, `notBefore` and `notAfter` that x509-parser reads.
