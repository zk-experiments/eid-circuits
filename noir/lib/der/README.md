# eid_der

Constrained DER reading for X.509 `TBSCertificate`s, their public keys and CMS signed attributes: every value a circuit takes from a certificate or SOD is read here, bound to the bytes that encode it.

## API

- **`read(der, offset, limit) -> Header`** returns `tag`, `header_len` and `len`.
  - Supported lengths: short form, `0x81 L` (L ≥ 0x80) and `0x82 L L` (first byte ≠ 0). Non-minimal and longer forms are rejected.
  - Asserts the element ends within `limit ≤ N`.
- **`expect(der, offset, limit, tag)`** is `read` plus a tag check.
- **`read_serial`** reads a positive INTEGER of 1–21 bytes (a 21st byte only as a leading `0x00`) and returns it right-aligned in 20 bytes.
- **`read_time`** reads UTCTime `YYMMDDHHMMSSZ` (years 50–99 → 19xx, 00–49 → 20xx, RFC 5280) or GeneralizedTime `YYYYMMDDHHMMSSZ` as unix seconds. It rejects non-digits, fractions and offsets, out-of-range fields, and years before 1970.
- **`parse_tbs(tbs)`** walks `SEQUENCE { [0] version, serialNumber, signature, issuer, validity, subject, subjectPublicKeyInfo, … }`. It returns `len` (from the outer header), `serial`, `not_before`, `not_after` and the `subjectPublicKeyInfo` offset. `validity` must contain exactly two times.
- **`read_uint::<N, L>`** reads a minimal non-negative INTEGER that fits `L` bytes and returns it right-aligned.
- **`spki_rsa::<N, K>(der, offset, limit) -> (modulus, exponent)`** reads an rsaEncryption or id-RSASSA-PSS `SubjectPublicKeyInfo`: the modulus right-aligned in `K` bytes, the exponent of at most 4 bytes.
- **`spki_ec(der, offset, limit, curve) -> (x, y)`** reads an id-ecPublicKey `SubjectPublicKeyInfo` whose parameters are `curve`'s named OID, or explicit `ECParameters` with `curve`'s `p`, `a` and `b`. The point must be uncompressed and full size. `curves::{P256, P384, P521, BP256, BP384, BP512}` are generated by `eid-vectors der`.
- **`parse_signed_attrs(attrs, md_offset) -> SignedAttrs`** walks CMS signed attributes in signed form (a SET of at most `MAX_SIGNED_ATTRS` = 8 attributes filling it exactly). It returns the length and the messageDigest value at `md_offset`, which must start an attribute with exactly one 20/28/32/48/64-byte value.
- **`parse_lds::<N, O, D>(lds, hash_oid, dg1_offset, dg11_offset, has_dg11) -> Lds`** walks an ICAO 9303 `LDSSecurityObject`:
  - version 0, or 1 with `ldsVersionInfo`;
  - the hash algorithm OID `hash_oid`, with optional NULL parameters;
  - at most `MAX_DATA_GROUPS` = 16 entries with `D`-byte hashes;
  - DG1 exactly once, at `dg1_offset`, and DG11 exactly once at `dg11_offset` when `has_dg11` (never otherwise).

  It returns the length and the offsets of both hash values.
- **`assert_zero_padded(buf, len)`** asserts that bytes past `len` are zero, so a bucket buffer has one representation.

## Review notes

- **Cost of witness offsets.** Offsets are witness-dependent, so every read is a dynamic array access (a ROM/RAM lookup in the backend). Cost grows with the number of reads, not with the buffer size.
- **Explicit curve parameters are bound by `p`, `a`, `b` only.** See docs/circuits/sod.md. Coefficients are compared as numbers, so SEC 1 fixed-width, `0x00`-prefixed and zero-stripped encodings all pass.
- **Day ranges aren't checked per month.** `days_from_civil` doesn't reject 31 February; such a certificate would parse to a nearby date. The certificate is signed, so this only matters if an issuer signs an invalid date.

## Tests

`src/vectors.nr` is generated by `eid-vectors der`. For 33 real certificates, `parse_tbs` must return exactly the length, serial, `notBefore` and `notAfter` that x509-parser reads, and `spki_rsa` / `spki_ec` the key csca-registry reads (12 of them use explicit EC parameters). Signed attributes and LDS security objects are covered by the SOD and envelope step tests in `noir/lib/steps`.
