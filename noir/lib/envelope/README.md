# eid_envelope

Encrypts DG1 (the MRZ) to one viewer key: a Grumpkin KEM with a Poseidon2 duplex as the DEM. [`rust/eid-envelope`](../../../rust/eid-envelope) implements the same construction: provers `seal` with it to build the witness, and viewers `open` with it. Generated vectors check that both agree field for field.

## Construction

For the viewer key `V₀` (the receiver's Grumpkin key, fresh per transfer, not `(0, 0)`), ephemeral scalar `e ≠ 0`, data key `K` and `context`:

1. **Ephemeral key.** `E = e·G`, with `G` Noir's embedded-curve generator (`std::embedded_curve_ops`).
2. **Key wrapping.** For each slot `i` (one, `VIEWERS = 1`): `S = e·Vᵢ`, `kᵢ = H(WRAP, S.x, S.y, i)`, `wrappedᵢ = K + kᵢ`. The point at infinity is rejected.
3. **Encryption.** `state = P(K, E.x, E.y, CIPHER)`, then `state[0] += context` and `state = P(state)`. Then for each block of three plaintext fields, `cⱼ = pⱼ + state[j]`, `state[j] = cⱼ`, `state = P(state)`.
4. **Plaintext.** 6 fields: `dg1_len`; `pack_be` of the 95-byte DG1 buffer (4 fields), as `csca_registry::pack_be` packs it; then a zero.

- `P` is the BN254 Poseidon2 permutation (width 4) and `H` Noir's Poseidon2 sponge (`csca_registry::hash`).
- `WRAP` and `CIPHER` are the ASCII strings `eid-envelope/wrap/v1` and `eid-envelope/cipher/v1` read as big-endian integers.

A viewer with secret `v` (`Vᵢ = v·G`) computes `v·E = e·Vᵢ`, unwraps `K`, and runs the duplex backwards: `pⱼ = cⱼ − state[j]`, `state[j] = cⱼ`.

## API

- **`seal(viewers, e, key, context, plaintext) -> Envelope`**: returns `ephemeral`, `wrapped[1]` and `ciphertext[6]`.
- **`plaintext(dg1, dg1_len)`**: builds the 6 plaintext fields. The caller asserts the buffer is zero past `dg1_len`.
- **`nullifier(scope, digest, digest_len)`**: the document's nullifier in `scope`, `H(NULLIFIER, scope, digest_len, pack_be(digest))` over the SOD's `messageDigest` zero-padded to 64 bytes, or 0 for scope 0 (see docs/circuits/envelope.md, *Nullifier*).
- Constants: `VIEWERS`, `DG1_MAX`, `PLAINTEXT_FIELDS`, `WRAP_DOMAIN`, `CIPHER_DOMAIN`, `NULLIFIER_DOMAIN`.

## Review notes

- **Freshness.** `e` and `K` must be uniformly random and never reused: reusing `(K, E)` reuses the keystream. The circuit only asserts `e ≠ 0`. `K` is a full field element masked by `kᵢ`, which is pseudorandom as long as the CDH-style assumption holds on Grumpkin and Poseidon2 behaves as a random oracle.
- **No authentication tag.** Integrity comes from the proof: it binds `C` to plaintext whose hash the issuer signed. A viewer must only trust an envelope whose proof verified on chain.
- **Fixed size.** The ciphertext always has 6 fields. The DG1 length is inside it, and only three lengths exist (TD1, TD2, TD3).
- **Context.** `context` (the transfer the envelope travels with) is absorbed before encryption, so a copied envelope attached to another transfer doesn't decrypt there and the step C proof doesn't verify under the other context.
- **The viewer key** is the receiver's, issued fresh for each transfer; it's a public input and isn't checked to be on the curve here, only `(0, 0)` is rejected. A reused key links transfers, and nothing enforces freshness. The receiver checks the proof's key is the one it issued before opening (docs/VERIFY.md, *Receiver*). The Rust `seal` rejects a missing or off-curve key.
- **Slot index in `kᵢ`.** `i` is always 0 now; it stays in the hash so the construction is unchanged if slots are added back.

## Tests

`src/vectors.nr` (generated by `eid-vectors envelope`) reseals an envelope over a synthetic TD3 DG1 and compares every published field, and checks a nullifier against `rust/eid-envelope`. Before emitting the vector, the generator opens it as each viewer. `src/tests.nr` covers the zero scalar, a missing viewer key, and key, ephemeral and context sensitivity, and the nullifier's scoping. `rust/eid-envelope` has its own tests: the Grumpkin and permutation known answers from `nargo`, a round trip, a missing key, a wrong secret or context, a short DG1, and bounds.
