# eid_rsa

RSA signature verification (RFC 8017) as used by CSCAs and DSCs: RSASSA-PKCS1-v1_5 and RSASSA-PSS with MGF1. Big-integer arithmetic is `noir-lang/noir-bignum` v0.10.0.

## Parameters

| generic | meaning |
|---|---|
| `MOD_BITS` | Modulus size in bits: 2048, 3072, 4096, 6144, … It must be a multiple of 8, and the modulus must have its top bit set (asserted). So `k = MOD_BITS / 8` bytes and `emBits = MOD_BITS − 1`. |
| `N` | Limbs: `ceil(MOD_BITS / 120)`. That's 18 for 2048, 26 for 3072, 35 for 4096 and 52 for 6144. |
| `E_BITS` | Exponent width. `exponent < 2^E_BITS` is asserted, and the exponent must be odd. 17 covers every exponent in the registry data: 3, 65537 and five others below 2¹⁷. |
| `D`, `P`, `S` | Digest length, DigestInfo length (15 for SHA-1, 19 otherwise), PSS salt length. |

`redc` is the Barrett constant `floor(2^(2·MOD_BITS + 6) / n)` in little-endian 120-bit limbs, computed off-circuit by the prover.

## API

- **`rsa::<N, MOD_BITS, E_BITS>(modulus, redc, exponent, signature)`** returns `s^e mod n`. It asserts the signature representative is at most `n` (see below for why `s = n` is harmless), then runs a left-to-right 2-bit fixed-window exponentiation over `E_BITS` bits (rounded up to even; the top bit is 0 when `E_BITS` is odd, since `exponent < 2^E_BITS` is asserted).
- **`verify_pkcs1v15::<N, MOD_BITS, E_BITS, D, P>(modulus, redc, exponent, signature, digest, digest_info)`** builds `EM = 00 01 FF…FF 00 ‖ DigestInfo ‖ digest` (at least 8 `FF` bytes, asserted through `k ≥ P + D + 11`) and asserts `s^e ≡ EM (mod n)`. `DIGEST_INFO_SHA1` … `DIGEST_INFO_SHA512` are the RFC 8017 prefixes with a NULL parameter.
- **`verify_pss::<H, N, MOD_BITS, E_BITS, D, S>(modulus, redc, exponent, signature, digest)`** implements EMSA-PSS-VERIFY (RFC 8017 §9.1.2) with MGF1 over the same hash `H: Digest<D>` and an `S`-byte salt:
  1. `m = s^e mod n` is forced canonical (`validate_in_field`) before its bytes are read.
  2. It checks `EM[k−1] = 0xBC` and that the top bit of `EM[0]` is 0.
  3. It computes `DB = maskedDB ⊕ MGF1(H, k − D − 1)` and clears the top bit.
  4. It checks that `DB` is `k − D − S − 2` zero bytes, then `0x01`, then the salt.
  5. It checks `H(0⁸ ‖ digest ‖ salt) = H`.
- **`mgf1::<H, D, L>(seed)`** is MGF1 (RFC 8017 §B.2.1).

## Soundness notes

- **`redc` can't break soundness.** noir-bignum only uses it inside unconstrained witness generation (`__barrett_reduction`), and every product is re-checked by constrained quadratic-expression evaluation. A wrong `redc` makes proving fail; it can't make a false statement verify.
- **Byte decoding is constrained.** `from_be_bytes` range-checks every 120-bit limb.
- **`s ≤ n`, not `s < n`, is enforced.** `validate_in_field` allows `s = n`, which is `0 mod n`, so `s^e ≡ 0`. That can't equal a PKCS#1 `EM` (which starts `00 01`). Under PSS, `m = n` would give `EM = n`'s bytes, and they fail the `0xBC` trailer check because `n` is odd.
- **The key isn't validated beyond its size.** The circuit using this library must bind `modulus` and `exponent` to the CSCA/DSC key it trusts (registry leaf or DSC `SubjectPublicKeyInfo`).
- **PKCS#1 v1.5 is strict.** DigestInfo must carry the NULL parameter. A signature that omits NULL is rejected, the same as the RustCrypto verifier the registry uses (it accepted every fixture).
- **PSS assumes the same hash for MGF1 and the message.** The registry reports any other combination as unsupported.
- **Cost:** with w = ⌈`E_BITS`/2⌉ windows, 2(w − 1) + 1 squarings and w multiplications (s² and s³ precomputed, the top window taken as is, each other window two squarings and a multiplication by 1, s, s² or s³): for `E_BITS` = 17, 17 squarings and 9 multiplications, against 17 and 17 for square-and-multiply (−9.4% to −13.6% on the RSA DSC and SOD steps). Specialising 65537 to 16 squarings and 1 multiplication would go further but makes the exponent a constant.

## Tests

- **`src/vectors.nr`** is generated by `rust/eid-vectors` (`cargo run -p eid-vectors -- rsa`) from real CSCA certificates in the DE and IT master lists. Every case is re-verified with RustCrypto before emission, and CI fails if the file is stale. The 19 cases:
  - PKCS#1 v1.5 with SHA-1, SHA-256, SHA-384 and SHA-512;
  - PSS with SHA-256 (salt 20 and 32), SHA-384 (salt 48) and SHA-512 (salt 20 and 64);
  - moduli of 2048, 3072, 4096 and 6144 bits;
  - exponents 3, 65537 and 107903.
- **`src/tests.nr`** mutates one vector at a time:
  - tampered signature (PKCS#1 and PSS);
  - other message digest (PKCS#1 and PSS);
  - other DigestInfo algorithm;
  - other exponent, even exponent, exponent wider than `E_BITS`;
  - signature not below the modulus;
  - modulus with the top bit clear;
  - PSS salt one byte shorter and one byte longer.
